🧠 Level 0: The Fundamentals (Zero Knowledge Assumed)

Welcome to Ground Zero

If you have never coded, never opened a terminal, or never understood how computers work under the hood, this curriculum is built for you. Before pressing buttons, we must construct an accurate physical and mental model of the computer hardware you are operating.

1. The Physical Computer & The Office Desk Analogy

Every computer consists of three fundamental hardware parts: the Hard Drive/SSD, the RAM (Memory), and the CPU (Processor).

Figure 1.1: Physical Computer Architecture — How software moves from storage into RAM, and how the CPU interacts with memory.
WHAT IT IS

Your computer is an electronic desk. The Hard Drive is the storage filing cabinet across the room. The RAM (Memory) is your physical desk surface. The CPU is the clerk sitting at the desk.

HOW IT WORKS

When you double-click an icon, the operating system copies the file's bytes from the slow SSD into RAM. Once in RAM, the CPU reads instructions and data numbers over the high-speed memory bus billions of times per second.

WHY IT EXISTS

CPUs work at light-speed (fractions of a nanosecond). Hard drives and SSDs are thousands of times too slow to feed the CPU directly. RAM was invented as a high-speed intermediary buffer so the CPU never sits idle waiting for storage.

HOW TO USE THIS IN PHANTOMSUITE

PhantomSuite never modifies files on your hard drive! PhantomSuite works entirely inside RAM while the program is alive. If you make a mistake, simply closing the game leaves your original files 100% untouched.

2. Bits, Bytes, Numbers & Hexadecimal

Computers don't have letters, words, or pictures. At the physical layer, computers are made of billions of microscopic transistors—electrical light switches that can only be OFF (0) or ON (1).

Figure 1.2: Anatomy of a Byte — 8 bits split into two 4-bit nibbles, mapping to exactly two Hex characters: 0xD5 (= 213 in decimal).
WHAT IT IS

A Bit is a single switch (0 or 1). A Byte is 8 switches grouped together, which can count from 0 up to 255. Hexadecimal is Base-16 counting (0-9 followed by A-F), where two symbols represent an entire byte.

HOW IT WORKS

Each group of 4 bits can represent 16 combinations ($2^4 = 16$). Because Hex has exactly 16 symbols ($0, 1, 2, ..., 9, A, B, C, D, E, F$), four bits map to exactly one hex character. Eight bits map to exactly two hex characters (e.g. 0xFF = 255).

WHY IT EXISTS

Humans cannot read strings of raw binary like 1101010111110000 without losing their minds. Hexadecimal compresses binary into readable, two-letter byte pairs without losing any mathematical precision.

HOW TO USE THIS IN PHANTOMSUITE

In the Hex Viewer (Tab 3), every pair of characters you see (like 48 89 5C) is exactly one byte. You can read, search, or edit bytes directly in hex.

3. Programs, Processes & Virtual Memory Bubbles

When you run a program on Linux, the kernel creates an isolated sandbox called a Process. Every process is assigned a unique numerical identity called a PID (Process ID).

Figure 1.3: Virtual Memory Architecture — How Linux keeps processes isolated, and how PhantomSuite inspects target memory via authorized kernel interfaces.
WHAT IT IS

A Program is an inactive executable file on your SSD. A Process is the live instance running in RAM with a unique PID number.

HOW IT WORKS

The Linux kernel uses hardware page tables inside the CPU (the MMU) to give each process an illusion: each process thinks it has the entire computer's memory to itself. Process A cannot write to Process B without raising a segmentation fault.

WHY IT EXISTS

Without virtual memory, one crashing program or malware could overwrite your entire operating system or steal passwords from other open windows.

HOW TO USE THIS IN PHANTOMSUITE

PhantomSuite uses the Linux system call process_vm_readv to read data across memory bubbles safely without pausing or crashing the target game.

4. Memory Addresses & The Postbox Analogy

Every byte in RAM has a number plate called its Memory Address. A Pointer is simply a variable whose content is the address of another variable!

Figure 1.4: Multi-Level Pointer Path — Moving from the static module base through heap objects to the final target variable.
WHAT IT IS

A Pointer is a memory slot holding a number that points to another slot. A Pointer Path is a chain of directions like: "Start at Game Base, add 0x5000, read the address inside, add 0x10, read that address, add 0x28 → Ammo!"

HOW IT WORKS

When game code creates objects using C++ new or C# new, the operating system allocates memory wherever it has free space on the heap, and stores the address in a pointer variable.

WHY IT EXISTS

Games cannot hardcode memory locations because levels, enemies, and weapons are created and destroyed dynamically while you play.

HOW TO USE THIS IN PHANTOMSUITE

Right-click any address in the Cheat Table → select 🧩 Find Pointer Paths (SMT Solver). PhantomSuite uses the Z3 solver to discover these paths automatically!

5. What is ASLR & Why Addresses Move on Every Launch

If you find your ammo address today, why does it break tomorrow when you restart the game?

Figure 1.5: Address Space Layout Randomization (ASLR) — The base address shifts randomly, but the relative offset (+0x4800) remains constant.
WHAT IT IS

ASLR stands for Address Space Layout Randomization. It is a security feature in the Linux kernel that places programs at a completely random memory address every time they start.

HOW IT WORKS

During the execve system call, the kernel generates entropy bits and applies a randomized offset to the memory map, shifting executable code, heap, and stack segments.

WHY IT EXISTS

ASLR prevents malicious hackers from using hardcoded memory addresses to hijack software via buffer overflow exploits.

HOW TO USE THIS IN PHANTOMSUITE

When you save a .phantom cheat table (Ctrl+S), PhantomSuite saves Module Base + Offset instead of the raw number. When you load the table, PhantomSuite recalculates the new base automatically!

6. The CPU Instruction Cycle, Registers & NOPing

How does the CPU actually execute code, and how does changing one byte give you infinite ammo?

Figure 1.6: 1-Click Code Patching — Replacing the decrement machine instruction with 0x90 (NOP = No Operation).
WHAT IT IS

The CPU fetches machine code bytes, decodes them into instructions (like sub rax, 1), and executes them. NOP stands for "No Operation" (byte opcode 0x90). When the CPU hits a NOP, it simply wastes one clock cycle doing nothing and moves to the next instruction.

HOW IT WORKS

In the Hex & Disasm Tab (Tab 3), clicking 🚫 NOP Instruction overwrites the exact bytes of the subtraction instruction with 0x90 using process_vm_writev.

WHY IT EXISTS

NOPing is superior to freezing numbers because freezing fights the game's code 20 times a second. NOPing permanently disables the subtraction at the source code level!

HOW TO USE THIS IN PHANTOMSUITE

Highlight the instruction in Tab 3 → click 🚫 NOP Instruction. To undo it, click ↩ Restore Original.

7. What Reverse Engineering Actually Is

WHAT IT IS

Reverse engineering is the scientific process of analyzing a compiled software system to understand its components, reconstruct its architecture, and inspect its runtime state without having access to the original source code.

HOW IT WORKS

We use PhantomSuite as an active diagnostic instrument: peeking into RAM pages, disassembling machine opcodes into assembly, tracing control flow graphs, and interrogating CPU register deltas.

WHY IT EXISTS

Developers and researchers reverse engineer binaries to audit security vulnerabilities, create compatibility mods, fix bugs in abandoned legacy software, unpack malware safely, and optimize performance.

HOW TO USE THIS IN PHANTOMSUITE

You now possess the foundational knowledge. Proceed to Level 1: Field Missions to execute your first real-world reverse engineering workflows!

Mission 2: Finding and Freezing Ammo / Gold

Figure 2.2: Multi-Pass Memory Filtering — How successive scans eliminate false positives through set intersection.
WHAT IT IS

Scanning all readable memory pages to pinpoint the exact 4-byte slot holding a variable.

HOW IT WORKS

Pass 1 snapshots every 4-byte integer matching your input. Pass 2 only checks the addresses from Pass 1, keeping only those that changed to the new value.

WHY IT EXISTS

RAM holds gigabytes of data. Millions of numbers exist simultaneously. Multi-pass intersection filtering is mathematically guaranteed to isolate variables in seconds.

PRACTICAL STEPS

  2. Shoot bullet in game (ammo now 49).
  3. Set Target: 49 → Click ⏩ Next Scan.
  4. Double-click remaining address → check Active (Freeze) → set value to 999.

Mission 3: Finding Values With No Numbers

WHAT IT IS

Locating health bars, stamina meters, or invisible timers that do not display numeric text on screen.

HOW IT WORKS

Instead of matching exact numbers, PhantomSuite compares the current byte values against the previous scan snapshot using relative math (Current < Previous or Current > Previous).

WHY IT EXISTS

Many games display visual UI bars (like red health bars) while storing the underlying health as a float or percentage between 0.0 and 1.0.

PRACTICAL STEPS
  1. Scan Type: Unknown Initial Value → Click 🔍 First Scan.
  2. Take damage in game → Scan Type: Decreased Value → Click ⏩ Next Scan.
  3. Stand still → Scan Type: Unchanged Value → Click ⏩ Next Scan (prunes timers).
  4. Heal with potion → Scan Type: Increased Value → Click ⏩ Next Scan.

Mission 8: Virtual CPU Sandbox & The Undo Stack (Micro-Emulator)

Figure 2.6: Sandboxed Micro-Execution — Isolated x86_64 CPU state and Copy-on-Write shadow memory.
WHAT IT IS

A virtual, sandboxed x86_64 CPU inside PhantomSuite that steps through functions one instruction at a time without running them in the real game.

HOW IT WORKS

Uses Capstone for decoding instructions and maintains a local dictionary of shadow memory pages. Reads from target RAM on demand, but all writes stay isolated in shadow pages.

WHY IT EXISTS

Testing unknown functions inside a real game can trigger anti-cheat bans, crash the game, or write corrupt data. The micro-emulator lets you test safely with a complete undo stack.

PRACTICAL STEPS
  1. Open ⚙️ Micro-Emulator (Tab 15).

  3. Press F7 (Step) to step instructions. Watch registers change color in neon orange!

Mission 9: Hunting Secret Keys & Encrypted Data (Entropy & Crypto Scanner)

Figure 2.7: Shannon Information Entropy Spectrum — Detecting encrypted memory buffers and mathematical crypto constants.
WHAT IT IS

A scanner that calculates the mathematical randomness of memory pages to identify encrypted buffers, packed shellcode, and cryptographic keys.

HOW IT WORKS

Computes Shannon Information Entropy ($H = -\sum p_i \log_2 p_i$). Also scans memory maps against signature tables for AES S-Boxes, SHA-256 vectors, and ChaCha20 constants.

WHY IT EXISTS

Encrypted data is mathematically indistinguishable from random noise ($H \ge 7.5$). Entropy analysis immediately reveals where decryption routines are storing secrets.

PRACTICAL STEPS
  1. Open 🔐 Entropy & Crypto (Tab 16).
  2. Click 🔐 Scan Process Memory.
  3. Matches for AES/SHA tables appear in the top table; high-entropy buffers appear in the bottom table. Double-click any row to view it in the Hex Viewer!

3. MicroEmulator (phantom_suite.core.micro_emulator)

from phantom_suite.core.micro_emulator import MicroEmulator

emu = MicroEmulator(target_pid=1234)
emu.set_reg("rip", 0x401000)

# Step single instruction
success, trace, reason = emu.step()
print(f"Executed: {trace.mnemonic} {trace.op_str}, New RAX: 0x{emu.get_reg('rax'):X}")

# Save snapshot
emu.save_snapshot()

# Run up to 100 steps or until ret
result = emu.run(max_steps=100)
print(f"Halt reason: {result.halt_reason}, Final RIP: 0x{result.final_rip:X}")

# Rollback on fault
if not result.terminated:
    emu.restore_snapshot()
